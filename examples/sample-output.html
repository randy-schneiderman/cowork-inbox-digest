Anthropic pushes back on the case for open-weight models

In a public exchange with investor Gavin Baker, Anthropic CEO Dario Amodei argued that open weights don't remove the power imbalance in AI, since whoever controls compute and chips still holds most of the leverage in practice. He also rejected the argument that regulation automatically produces regulatory capture, pointing instead to tiered rules designed to slow frontier labs while leaving smaller players less constrained. The exchange raises an open question for regulators: how to identify frontier-level capability before open weights can be copied, modified, and stripped of safety guardrails.

Platform / DevOps angle: this is a policy fight, not a technical one, but the outcome affects what you're allowed to self-host and fine-tune versus what stays API-only. Worth tracking if any part of your AI infrastructure roadmap assumes open-weight models stay unrestricted.

Source: The New Stack (newsletter)

AI coding startups are raising at valuations that assume winner-take-most

Three AI coding startups closed large rounds in the same week. Code Rabbit (AI code review, security/governance focus) raised a $143M Series C at a $1.5B valuation. Lovable raised $400M at a $13.3B valuation, roughly double its December figure, reportedly on the back of $500M in annualized run-rate revenue (per TechCrunch). Cognition (maker of Devin) is reportedly in talks for $1B at a $40B valuation (per Bloomberg), after raising at $26B earlier this year. Separately, several public companies cited high AI-generated code shares: Google's CEO said 75% of its code is AI-written, Snap's CEO cited 65%, Airbnb's CEO cited 60%.

Platform / DevOps angle: the funding volume assumes most teams stay multi-tool during an experimentation phase and then consolidate to two or three vendors, the way streaming did. Worth asking now which coding tools your org would actually keep if forced to cut down, before that consolidation happens on someone else's timeline.

Deloitte survey: enterprises are stuck between piloting agents and scaling them

A Deloitte survey of 500+ US business and IT leaders found 42% have tested or deployed AI agents, but only 15% have scaled multi-agent systems across the business. Only 21% said their business processes are actually prepared for agentic AI. Cited blockers: inaccessible or fragmented data, difficulty governing agents, and costly integration work, not model quality. Deloitte's Laura Shact is quoted warning that "limited, layered-on approaches may create the sense of getting ahead with quick wins, but in reality, they may not be enough."

Platform / DevOps angle: this matches the pattern behind most failed agent rollouts: teams bolt an agent onto an existing workflow instead of redesigning the workflow, then blame the model when it doesn't hold up. If you're scoping agent work, the data plumbing and governance layer is very likely the actual bottleneck, not model selection.

Source: The Deep View / AI for Work (newsletter), citing a Deloitte survey.

A worked example of a self-hosted LLM inference stack: FastAPI, vLLM, Docker, GPU

A walkthrough project builds and containerizes an LLM inference service: FastAPI as the gateway, vLLM as the inference engine, a Hugging Face model, and a Streamlit frontend, all containerized with Docker for a GPU-backed deployment. It details the request path (tokenization, continuous batching, PagedAttention-based KV cache management so more concurrent requests fit in VRAM) and calls out real operational concerns: cold start while the model loads into VRAM (1-3 minutes, not a bug), GPU memory sizing per model (roughly 3GB for a 1.5B-parameter model vs. roughly 8GB for a Phi-3 Mini), and the tradeoff between fixed-cost self-hosted GPU spend and per-token hosted API billing. Framed by the sender as a beginner/resume project, but the actual content, GPU memory sizing, batching, KV cache management, is production-relevant.

Platform / DevOps angle: this is a reasonably accurate, if compressed, mental model of what actually runs behind a self-hosted inference endpoint. Useful as a sanity check if you're evaluating self-host vs. API for an internal model-serving decision, or briefing a team member new to GPU-backed workloads.
